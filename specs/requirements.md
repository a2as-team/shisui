# Requirements Document

## Introduction

Shisui is a student learning assistant application designed to help students manage their study schedules, research course materials, and test their knowledge through automated assessments. The system uses an agent-to-agent (A2A) architecture where a main planner agent coordinates with specialized agents (course agent and exam agent) to provide comprehensive learning support. The frontend is a clean, chatbot-like interface built with TypeScript/Next.js, while the backend uses Python-based agents with tool systems for web search, timer management, and test generation.

## Glossary

- **Shisui System**: The complete student learning assistant application including frontend and backend components
- **Planner Agent**: The main coordinating agent that handles student questions and routes requests to specialized agents
- **Course Agent**: A specialized agent that researches course materials using web search and manages study timers
- **Exam Agent**: A specialized agent that generates and administers tests based on studied material
- **Tool System**: Python-based functions that agents can invoke to perform specific actions (web search, timers, test generation)
- **A2A (Agent-to-Agent)**: Communication pattern where agents delegate tasks to other specialized agents
- **Perplexity API**: Web search API used by the Course Agent to find relevant study materials
- **Study Session**: A timed period during which a student focuses on specific course material
- **Assessment**: A test or quiz generated by the Exam Agent based on studied content

## Requirements

### Requirement 1: Student Query Handling

**User Story:** As a student, I want to ask questions about my studies in natural language, so that I can get personalized help with planning, learning, and testing.

#### Acceptance Criteria

1. WHEN a student submits a query through the chat interface THEN the Shisui System SHALL route the query to the Planner Agent
2. WHEN the Planner Agent receives a query THEN the Planner Agent SHALL analyze the intent and determine which specialized agent should handle the request
3. WHEN the query requires course research THEN the Planner Agent SHALL delegate to the Course Agent
4. WHEN the query requires test generation THEN the Planner Agent SHALL delegate to the Exam Agent
5. WHEN the query is general planning or coordination THEN the Planner Agent SHALL respond directly without delegation

### Requirement 2: Course Material Research

**User Story:** As a student, I want the system to research relevant study materials for my courses, so that I can access high-quality learning resources without manual searching.

#### Acceptance Criteria

1. WHEN the Course Agent receives a course research request THEN the Course Agent SHALL formulate appropriate search queries based on the course topic
2. WHEN the Course Agent formulates search queries THEN the Course Agent SHALL invoke the Perplexity API web search tool to retrieve relevant materials
3. WHEN the Course Agent receives search results THEN the Course Agent SHALL filter and rank results by relevance to the course topic
4. WHEN the Course Agent presents materials THEN the Course Agent SHALL include source citations for all retrieved content
5. WHEN the Course Agent completes research THEN the Course Agent SHALL return formatted results to the Planner Agent for presentation to the student

### Requirement 3: Study Timer Management

**User Story:** As a student, I want the system to set study timers for me, so that I can maintain focused study sessions with proper time management.

#### Acceptance Criteria

1. WHEN a student requests a study timer THEN the Course Agent SHALL create a timer with the specified duration
2. WHEN the Course Agent creates a timer THEN the Course Agent SHALL invoke the timer tool with the duration parameter
3. WHEN a study timer is active THEN the Shisui System SHALL display the remaining time to the student
4. WHEN a study timer expires THEN the Shisui System SHALL notify the student that the study session has ended
5. WHEN a study timer expires THEN the Shisui System SHALL offer to start an assessment through the Exam Agent

### Requirement 4: Test Generation and Administration

**User Story:** As a student, I want the system to generate tests based on what I've studied, so that I can assess my understanding and identify knowledge gaps.

#### Acceptance Criteria

1. WHEN a student completes a study session THEN the Exam Agent SHALL generate a test based on the studied material
2. WHEN the Exam Agent generates a test THEN the Exam Agent SHALL create questions that cover key concepts from the study material
3. WHEN the Exam Agent presents a test THEN the Exam Agent SHALL display questions one at a time or as a complete set based on test configuration
4. WHEN a student submits test answers THEN the Exam Agent SHALL evaluate the responses for correctness
5. WHEN the Exam Agent completes evaluation THEN the Exam Agent SHALL provide a score and detailed feedback on incorrect answers

### Requirement 5: Agent-to-Agent Communication

**User Story:** As a system architect, I want agents to communicate seamlessly with each other, so that the system can provide coordinated responses across multiple specialized domains.

#### Acceptance Criteria

1. WHEN the Planner Agent delegates to a specialized agent THEN the Planner Agent SHALL pass all relevant context from the student query
2. WHEN a specialized agent completes its task THEN the specialized agent SHALL return results to the Planner Agent
3. WHEN the Planner Agent receives results from a specialized agent THEN the Planner Agent SHALL format and present the results to the student
4. WHEN multiple agents are involved in a query THEN the Shisui System SHALL maintain conversation context across agent transitions
5. WHEN an agent transfer occurs THEN the Shisui System SHALL display which agent is currently handling the request

### Requirement 6: Chat Interface

**User Story:** As a student, I want a clean, intuitive chat interface, so that I can interact with the system naturally without technical complexity.

#### Acceptance Criteria

1. WHEN a student opens the application THEN the Shisui System SHALL display a chat interface with a text input field
2. WHEN a student types a message THEN the Shisui System SHALL display the message in a user chat bubble
3. WHEN an agent responds THEN the Shisui System SHALL display the response in an assistant chat bubble with agent identification
4. WHEN an agent uses a tool THEN the Shisui System SHALL display a tool indicator showing the tool name and status
5. WHEN the interface displays messages THEN the Shisui System SHALL auto-scroll to show the most recent message

### Requirement 7: Tool System Architecture

**User Story:** As a developer, I want a modular tool system for agents, so that new capabilities can be added without modifying agent core logic.

#### Acceptance Criteria

1. WHEN an agent needs to perform a specific action THEN the agent SHALL invoke the appropriate tool from the tools folder
2. WHEN a tool is invoked THEN the tool SHALL execute its function and return results to the calling agent
3. WHEN a new tool is added to the tools folder THEN the tool SHALL be available to agents without requiring agent code changes
4. WHEN a tool encounters an error THEN the tool SHALL return an error message that the agent can present to the student
5. WHEN a tool completes successfully THEN the tool SHALL return structured data that agents can process and present

### Requirement 8: Web Search Integration

**User Story:** As a student, I want the system to access current information from the web, so that I can study the most up-to-date materials and research.

#### Acceptance Criteria

1. WHEN the Course Agent needs current information THEN the Course Agent SHALL invoke the Perplexity API search tool
2. WHEN the search tool is invoked THEN the search tool SHALL send the query to the Perplexity API
3. WHEN the Perplexity API returns results THEN the search tool SHALL parse and structure the response data
4. WHEN search results include citations THEN the search tool SHALL extract and format citation information
5. WHEN the search tool returns results THEN the results SHALL include both answer content and source citations

### Requirement 9: Study Session Workflow

**User Story:** As a student, I want a guided workflow from research to study to testing, so that I can follow an effective learning process.

#### Acceptance Criteria

1. WHEN a student requests help with a topic THEN the Planner Agent SHALL offer to research materials through the Course Agent
2. WHEN course materials are presented THEN the Planner Agent SHALL offer to start a timed study session
3. WHEN a study session completes THEN the Planner Agent SHALL offer to generate a test through the Exam Agent
4. WHEN a test is completed THEN the Planner Agent SHALL offer to research additional materials for topics with incorrect answers
5. WHEN the workflow completes THEN the Planner Agent SHALL summarize the student's progress and suggest next steps

### Requirement 10: Response Formatting and Citations

**User Story:** As a student, I want clear, well-formatted responses with proper citations, so that I can trust the information and explore sources further.

#### Acceptance Criteria

1. WHEN an agent presents information from web search THEN the agent SHALL format the response in clean, natural language
2. WHEN an agent presents information with sources THEN the Shisui System SHALL display citations separately from the main content
3. WHEN citations are displayed THEN the Shisui System SHALL show source URLs and titles
4. WHEN a student views a citation THEN the Shisui System SHALL allow the student to click through to the original source
5. WHEN an agent response includes markdown formatting THEN the Shisui System SHALL render the markdown properly in the chat interface
